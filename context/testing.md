# Testing

No test framework existed in this project before `changes/001-api-spa-rewrite/`. Established during that change's test-planning:

- **Backend**: pytest. Standard Flask test client for integration tests.
- **Database in tests**: real Postgres via Docker, never SQLite — even though SQLite is allowed for local dev convenience. Tests must catch schema/constraint/type behavior that only shows up on the real production database type. Reuses the Docker setup already planned for deployment, rather than adding a second, different local-only test setup.
- **Mock boundary default**: real dependencies (DB) wherever controlled; prefer a real safe test environment for uncontrolled external services when one exists and is actually reliably repeatable; otherwise mock at the HTTP client layer.
- **SimpleFIN correction (`simplefin-connect.md`, 2026-08-10)**: SimpleFIN *does* have a public demo bridge with a reusable-by-documentation setup token — the earlier assumption here ("no sandbox exists") was wrong. But "reusable" turned out not to mean "safe to re-exchange on every automated test run": manual `curl` verification succeeded, then a handful of real pytest runs during that slice's development exhausted it (`403 Forbidden — was it already claimed?`, non-transient). The **claim/exchange step specifically** is now mocked at the HTTP client layer for that reason — it's a one-time, semi-consumable operation, not a stable read endpoint. This does NOT necessarily apply to `/accounts` polling once already-connected (a read against an established Access URL) — verify that independently in `simplefin-sync.md` rather than assuming the same limitation, and don't assume the reverse either (that it's safe) without checking. (SimpleFIN itself is superseded by Plaid as of `changes/004-plaid-and-self-host/` — kept here as the cautionary precedent behind the next entry.)
- **Plaid Sandbox is the opposite case (`plaid-connect.md`, 2026-08-26, agent-proposed — not yet human-confirmed)**: unlike SimpleFIN's demo bridge, Plaid Sandbox is explicitly designed for repeated automated use — "create an unlimited number of test Items," default credentials (`user_good`/`pass_good`) work repeatedly across institutions, and `/sandbox/public_token/create` generates a fresh `public_token` programmatically without touching the Link UI at all. Both `/link/token/create` and `/item/public_token/exchange` are called for real against Sandbox in tests, nothing mocked — the "uncontrolled WITH a reliably repeatable test environment" row of the mock-boundary table above, not the SimpleFIN row. Don't default to mocking a new provider's exchange step just because SimpleFIN's needed it — check whether the provider's *own* Sandbox is actually built for reruns first, the way this check was skipped the first time.
