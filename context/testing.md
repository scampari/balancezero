# Testing

No test framework existed in this project before `changes/001-api-spa-rewrite/`. Established during that change's test-planning:

- **Backend**: pytest. Standard Flask test client for integration tests.
- **Database in tests**: real Postgres via Docker, never SQLite — even though SQLite is allowed for local dev convenience. Tests must catch schema/constraint/type behavior that only shows up on the real production database type. Reuses the Docker setup already planned for deployment, rather than adding a second, different local-only test setup.
- **Mock boundary default**: real dependencies (DB) wherever controlled; prefer a real safe test environment for uncontrolled external services when one exists and is actually reliably repeatable; otherwise mock at the HTTP client layer.
- **SimpleFIN correction (`simplefin-connect.md`, 2026-08-10)**: SimpleFIN *does* have a public demo bridge with a reusable-by-documentation setup token — the earlier assumption here ("no sandbox exists") was wrong. But "reusable" turned out not to mean "safe to re-exchange on every automated test run": manual `curl` verification succeeded, then a handful of real pytest runs during that slice's development exhausted it (`403 Forbidden — was it already claimed?`, non-transient). The **claim/exchange step specifically** is now mocked at the HTTP client layer for that reason — it's a one-time, semi-consumable operation, not a stable read endpoint. This does NOT necessarily apply to `/accounts` polling once already-connected (a read against an established Access URL) — verify that independently in `simplefin-sync.md` rather than assuming the same limitation, and don't assume the reverse either (that it's safe) without checking.
